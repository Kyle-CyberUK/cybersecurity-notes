# SIEM

## Overview
- Covers what a SIEM is, how it collects and correlates logs from across a network, and how SOC Analysts use it to detect and investigate threats.

## Key Concepts
- A **SIEM (Security Information and Event Management)** system collects logs from multiple devices across a network.
- It centralises and stores the logs, then performs correlation to identify suspicious activity and generate alerts.

## Log Source Types
- **Host-Centric** - Events occurring on a specific device. Examples include: Windows Event Logs, Sysmon, registry changes, failed logins.
- **Network-Centric** - Events generated by network communication. Examples include: VPN logs, firewall logs, DNS queries

## Common Log Locations
- Windows records every event which can be viewed using Event Viewer.
- Linux stores some logs in: `/var/log/auth.log`, `/var/log/httpd`, and `/var/log/kern`

## How SIEM works
- Log Sources → Ingestion → Normalisation → Correlation → Alert → Analyst
- **Ingestion** - Logs are collected from endpoints, servers, firewalls, and network devices.
- **Normalisation** - Raw logs are converted into a consistent, readable format.
- **Correlation** - Rules are applied to detect patterns that indicate a threat.
- **Dashboards** - Summarise activity and present actionable insights to analysts.

## SOC Analyst Responsibilities in SIEM
- Monitor and investigate alerts.
- Identify and tune false positives.
- Report on incidents and compliance.
- Identify blind spots in network visibility.

## Relevance
- SIEM is the primary tool used by SOC Analysts daily.
- Understanding how logs are ingested, normalised, correlated, and how to triage alerts on a dashboard is core to L1/L2 analyst work and directly applicable to any blue team or incident response role.
